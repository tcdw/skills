# tcdw 的文风（2020–2024）

依据：tcdw 2020–2024 年的 13 篇博文（评测、教程、年终总结），合计约 1 万字。下面的例句都是原文，没有改写。数字是全量统计。

改稿时把这些当作「tcdw 会怎么写」的参照，不要当成必须满足的清单：一段话里用上一两条就够了。

## 句子

**主句只说事实，补充放进括号。** 左括号每千字约 7 个。限定条件、吐槽、例子、来源都放括号里。

> 但我的需求不高（就是存取文件和下载啥的，顺便开个 web 服务器），即使是看动画的话，解码都在客户端完成，所以也就 Gen10 了。
> 当然，这样的业余机房也不是没有代价的；一个是噪音比较大（就这我还没考虑机架式服务器），还有一个是电费要比以前高出不少（好在内蒙古的电价相对还是很低的）。

**每个决定都讲理由。** 「因为」「所以」各约 2.4 次 / 千字。买什么、换什么、为什么这样装，都会说出原因。

> 因为卖家发的是顺丰，所以我下单以后第三天就到了。
> 我那个 Gamemax 机箱正好附送了一根这样的转接线，所以我就直接拿来用了。

**段落是正常中文文章的段落，不要切碎。** tcdw 的一句话本身就长（逗号多，一句常有 30–50 字），所以一段通常是一到三句、四五十字左右（叙述段落中位数约 41 字，一半落在 23–60 字之间），年终总结的段落更长。只有很短的结果句或者转折，才会单独成段。

> 我之前的确考虑过 CPU 的问题，毕竟这玩意是焊在主板上的。但我的需求不高（就是存取文件和下载啥的，顺便开个 web 服务器），即使是看动画的话，解码都在客户端完成，所以也就 Gen10 了。
> 安装过程没什么坑，一切都在预料之中。随后，我通过 apt 安装了各种我需要的软件（nginx、Aria2、Transmission 等），写好 `/etc/fstab` 表，就大功告成了。

单独成段的短句，一篇里只有几处，用在结果或转折上：

> 最终，成功在国内商家以 6.8k 拿下。

反例：把同一件事的几个短句拆成好几段，读起来像聊天记录，不像文章。

```text
安装就是关机、插卡、开机。

TrueNAS Scale 能直接识别 i226-V，不用额外装驱动。
```

应该合成一段：「安装就是关机、插卡、开机。TrueNAS Scale 能直接识别 i226-V，不用额外装驱动。」

**句子写完整，不要写成电报体。** 口语化不等于省字。tcdw 的句子通常有主语「我」，前后分句之间用「所以」「以后」「倒是」「反倒」这类词接起来；先给判断，再说细节。去 AI 腔的时候最容易矫枉过正，写出「用久了发现」「跑分啥的无所谓」「就是 A、B、C，没什么坑」这种被砍掉一半的句子。

> 安装过程没什么坑，一切都在预料之中。

下面是 tcdw 亲自把改稿再改一遍的几处（左边是改稿，右边是 tcdw 改后的）：

| 改稿 | tcdw 改成 |
| --- | --- |
| 安装就是关机、插卡、开机，没什么坑。TrueNAS Scale 能直接识别 i226-V，不用额外装驱动。 | 安装倒是没什么坑，就是关机、插卡、开机。TrueNAS Scale 能直接识别 i226-V，所以不用额外装驱动。 |
| 用久了发现，卡脖子的其实是那个千兆网口 | 久而久之，我发现卡脖子的其实是那个千兆网口 |
| 换完才发现，感觉跑分啥的其实无所谓，能放心用下去才最重要 | 换完以后，我反倒没那么在乎跑分了，感觉能放心用下去才是最重要的 |
| 体感上更明显：以前备份是件得专门等着的事 | 体感上更明显，以前备份是件得专门等着的事 |
| 结果项目直接跑不起来了 | 结果项目直接炸掉了 |

从这几处能看出来：

- 判断放前面（「倒是没什么坑」），细节放后面（「就是关机、插卡、开机」）。
- 因果关系哪怕很明显，也用「所以」连上。
- 时间用「以后」，不用「之后」（2020–2024 年「以后」12 次，「之后」0 次）。
- 补上主语「我」，用「是……的」把话说全（「才是最重要的」）。
- 顺着往下说的时候用逗号，冒号留给「下面要列东西了」和「答案是」。
- 出故障说「炸（掉）了」：「如果项目中有使用到 Web Worker，肯定会炸掉」。

**先用「其实」让一步，再用「但是」转。** 要换掉或批评一个东西之前，先承认它本来还行。

> 其实这台机器的性能直到今天依然不算逊色，基本上可以满足日常使用。但是，因为一些个人原因，我开始日常需要开启多个虚拟机，于是这台机器的 CPU 就开始有些吃不消了。

**分号的两种用法。** 图注式的「东西；补充一句」，以及在一句里串起「原因；后果；不过……」。

> 东芝 DT01ACA200 机械硬盘（2TB / CMR）；拆下来以后被我塞进 NAS 里了。

**提方案：「想到了一个主意：」「换一个思路：」**，冒号后面才是做法。

> 由于 Vite 使用了 esbuild 进行编译速度的提升，我们想到了一个主意：借助 [esbuild-loader](https://github.com/privatenumber/esbuild-loader)，把 Vue CLI 中的 Babel 替换为 esbuild。

**自问自答用「那么……呢？」**，下一句马上用自己试过的结果回答。

> 那么把整个散热器都拆掉呢？我试了，结果机器在 POST 就会报错，抱怨风扇出现了问题。

**「如果你……」给另一类读者留出口**，常常顺手推荐自己没选的方案。

> 不过，如果你没有长期使用 Windows 远程桌面的需求，而且只想玩一些大众游戏，那么类似于 [网易云游戏平台](https://cg.163.com/)、[腾讯云游戏](https://start.qq.com/) 等服务都是可以考虑的。

**省略号停一拍。** 句中停一下再揭晓，或者放在句尾表示「就这样吧」。

> 中间那个横着的玩意是……显卡风扇。
> 所以，总体上感觉今年是碌碌无为的一年。不过没办法……

**加粗只标事实、坑和规格**，不标感悟。

> 这些数值可以酌情调整。但是，**请确保有足够的剩余空间。**
> 但是这台机器的**风扇接口也是非标准的**，就有点尴尬。

## 用词

**语气词很少**，全部加起来每千字约 2 个。每个都有固定用法：

| 词 | 用法 | 例 |
| --- | --- | --- |
| 吧 | 推测、走一步看一步，常跟「大概」连用 | 所以这篇博文大概还是能发挥余热吧。 |
| 啊 | 跟在理由后面抱怨 | 因为这玩意即使是对开发者也很不友好啊。 |
| 啦 | 对自己无所谓、或者说到好处 | 不过对我来说无所谓啦。 |
| 呢 | 只用在问句里，不用在陈述句尾 | 嗯，那么这个 mixin 是干什么的呢？ |
| 嗯 | 句首，想一下再说 | 嗯，我觉得目前就足够了。 |
| 好耶 | 事情办成了 | 经过一系列的努力，我们终于拥有了在 IE11 正确显示的多列卡片列表。好耶！ |

**半括号自嘲**：段落或文章的最后一句，开了括号不关，后面跟一个动作词或什么都不跟。一篇文章一两处就够了。

> 当然更好的方法是，提桶跑路，去给历史包袱不重的项目填坑（逃
> 结果我的 1650 Super 反而成瓶颈了（

**删除线**：一种是说完正经话补一句玩笑；另一种是划掉过时的信息，后面接新情况。

> ~~别人花 648 抽优菈，我花 648 让游戏跑起来（笑~~
> ~~服务端（工作站）和客户端都在重重 NAT 之下。~~现在不是问题了，家里和移动网络**都有公网 IPv6**，可以点对点直连。

**常用词：**

- 连接词：「不过」最多（每千字约 2.8 次）；好消息用「不过幸运的是」；岔开说一句用「顺便」「顺便一提」；补一条用「同时」「以及」。
- 动手：拿下、丢进、塞进、开刀、搞。
- 指代东西：「这玩意」。
- 步骤收尾：就是了、就可以了、就搞定了、大功告成。
- 正面判断：爽、香、滑溜溜、好用。负面判断：尴尬、蛋疼、离谱。
- 限定：「（至少……）」「对我来说」「感觉」。判断多用「感觉」开头，很少说「我认为」。
- 推测：「大概」「可能」「应该」，不用「也许」「或许」。
- 举例：通常塞进括号，写成「（如 Teamviewer）」「（比如我）」，很少单独写「比如……」一句。
- 圈内黑话（适量）：社畜、好文明、气抖冷、提桶跑路、苦逼、迷惑行为、TAT。
- 称呼自己的文章：「这篇博文」「本博文」，不说「本文」。

## 段落之间

- **评测和总结按时间走**：小节第一句用「随后」「在此之前」「近两周以后」「随着……」开头。
- **教程按步骤走**：小节第一句直接用「首先」给操作；段首用「接下来」「然后」推进，遇到问题用「然而」拐弯。
- **前后呼应**：先埋一句「（见后文）」，后面再兑现；同一个具体东西（比如一张显卡）在文中出现两三次，最后一次变成笑点。
- 小节开头不回顾上一节做了什么。

## 「我」和读者

- 「我」讲经历：买了什么、遇到什么、感觉怎样。
- 「我们」有两种：团队（「我们的门户网站项目」），以及教程里拉着读者一起做（「我们需要修改……」）。
- 「你」只写条件和结果：「如果你……」「你的编译产物会出现在……」。
- 「大家」只在结尾的祝福里出现。不叫读者「朋友们」「小伙伴们」。
- 自嘲多，说教少。不写「希望大家引以为戒」这类话。
- 标边界：「本博文不是真正意义上的教程」「（至少现今）」。
- 让功：写明是谁介绍的、谁指正的（「经过 JackWorks 的指正，代码改成了这样。」「在 @qwe7002 的介绍下」）。
- 后来补充的内容写成「2021 年 4 月更新：」「Update:」「Edit:」，放在正文里，不删旧内容；过时的旧内容用删除线划掉。

## 格式细节

- 中文和英文、数字之间加空格：「Vue 2 项目」「6.8k 拿下」「第三天」。
- 中文标点用全角。
- 引号用「」。只给直接引语、界面文字、专门的叫法加引号，不给普通概念加引号。
- 「的」常常当「地」用（「顺利的完成」「意志坚定的选择」），这是 tcdw 的习惯，轻改时保留，不要统一改成「地」。

## 这个时期不用的词

以下这些在 2020–2024 年的语料里是 0 次，改稿时不要引入：

- 换句话说、也就是说、顺带一提、值得一提的是、需要注意的是、众所周知、总而言之、综上、让我们、干货、其次、笔者、本人、本文、也许、或许、恰恰
- 「不是……而是……」对照句
- emoji
- 粗口、「母上大人」、「菊苣」、「奇怪的」（这些是 2017–2019 年的写法，现在已经不用了）
