# Verify on Device

在 React Native 项目的可用移动设备上运行并验证当前改动，使用 `agent-device` 完成交互、检查和证据收集。

## 平台选择

如果用户明确指定了平台或设备，优先遵循用户的指定。

如果用户没有指定平台，按以下顺序选择：

1. 已连接并可用的 Android 物理设备
2. 如果当前系统是 macOS，使用 iOS Simulator
3. 自动启动一个 Android Emulator

不得因为 Android Emulator 已经容易启动，就跳过可用的 Android 物理设备或 macOS 上的 iOS Simulator。

### Android 物理设备

通过 ADB 检查是否存在状态为 `device` 的物理 Android 设备。

不要把以下目标视为可用物理设备：

* 状态为 `offline` 的设备
* 状态为 `unauthorized` 的设备
* Android Emulator
* 无法正常安装或启动应用的设备

如果存在多个 Android 物理设备，并且用户没有指定设备，选择最适合当前项目的可用设备。无法可靠判断时，使用列表中的第一个可用物理设备，并在结果中说明设备标识。

### iOS Simulator

仅在 macOS 上使用 iOS Simulator。

优先复用已经启动且可用的 Simulator。如果没有可用实例，自动启动一个与项目兼容的 Simulator。

记录 Simulator 是否由本次验证流程启动，以便验证结束后正确清理。

### Android Emulator

只有在以下条件均成立时，才自动启动 Android Emulator：

* 用户没有明确指定其他平台
* 没有可用的 Android 物理设备
* 当前环境不能使用或不应优先使用 iOS Simulator

选择一个与项目最低 Android 版本和当前工具链兼容的 AVD。

等待 Emulator 完成启动并进入可交互状态后，再安装或启动应用。不要在 `adb` 刚刚发现设备时就立即开始验证。

记录 Emulator 是否由本次验证流程启动。

## 验证准备

开始操作前：

1. 阅读项目中的 `AGENTS.md`、README、开发文档和相关 package scripts。
2. 判断项目使用 Expo、React Native CLI，还是项目自定义的启动方式。
3. 检查 Metro、Expo Dev Server 或其他必需服务是否已经运行。
4. 尽量复用现有开发服务，避免启动重复实例。
5. 确认目标设备能够连接到开发服务。
6. 确认当前工作区中的改动已经被应用到待验证的构建中。

不要擅自执行生产发布、签名、上传商店或修改远程环境。

## 使用 agent-device

设备交互必须优先使用 `agent-device`。

使用 `agent-device` 完成：

* 启动或切换到待验证应用
* 点击、输入、滚动和返回
* 检查界面元素和可访问性树
* 验证用户要求的操作路径
* 捕获必要的截图、错误信息或界面状态

不要仅凭应用成功编译或成功启动，就判断验证通过。

不要在可以通过语义化元素、文本、测试标识或可访问性信息定位控件时，依赖脆弱的绝对坐标。

如果 `agent-device` 无法识别关键控件：

1. 检查应用是否存在可访问性问题。
2. 尝试通过稳定的文本、accessibility label、testID 或层级信息定位。
3. 只有在必要时才使用坐标操作。
4. 在结果中记录导致绕行的可访问性问题，并且建议用户指挥 Agent 进行进一步的修改。

## 验证范围

根据用户当前请求和工作区改动，选择最小但足够的验证范围。

至少验证：

* 应用能够启动并进入相关页面
* 改动涉及的主要交互路径可以完成
* 页面没有明显崩溃、卡死或阻断性错误
* 相关状态变化符合预期
* 没有观察到与本次改动直接相关的明显回归

如果用户只说“验证当前改动”，先检查 diff 和相关上下文，再推断需要覆盖的路径。

不要无边界地遍历整个应用。

## 问题处理

如果验证失败：

1. 收集可复现步骤。
2. 记录实际结果与预期结果。
3. 检查 Metro、原生日志和设备日志中与失败直接相关的信息。
4. 区分以下失败类型：

   * 产品或代码问题
   * 构建问题
   * 开发服务问题
   * 设备连接问题
   * `agent-device` 操作或识别问题
   * 测试环境问题
5. 不要为了让验证“通过”而掩盖、忽略或绕过真实错误。

除非用户同时要求修复，否则本 Skill 默认只负责验证和报告，不主动修改代码。

## 清理

验证结束后，无论成功还是失败，都要执行清理。

### 物理 Android 设备

不要关闭、重启或断开物理设备。

可以将应用留在当前状态，除非用户另有要求。

### iOS Simulator

验证结束后关闭 iOS Simulator。

如果 Simulator 在执行本 Skill 前已经运行，优先只关闭本次使用的应用；不要影响用户正在使用的其他 Simulator。

如果 Simulator 是本次流程自动启动的，关闭对应 Simulator；在不存在其他用户工作负载时，可以退出 Simulator 应用。

### Android Emulator

验证结束后关闭本次用于验证的 Android Emulator。

如果 Emulator 是本次流程自动启动的，必须停止该 Emulator。

如果 Emulator 在执行本 Skill 前已经运行，不要直接关闭用户已有实例；只停止应用并恢复到合理状态，除非用户明确要求关闭。

### 其他进程

只关闭本次流程自行启动、并且不再需要的临时进程。

不要关闭执行前已经存在的 Metro、Expo Dev Server、终端会话或其他开发服务。

即使验证中途失败，也必须尝试执行清理步骤。

## 输出

验证完成后，用简洁格式报告：

* 使用的平台和设备
* 验证的操作路径
* 验证结果：通过、部分通过或失败
* 观察到的问题
* 与可访问性或 `agent-device` 操作有关的障碍
* 是否启动并关闭了 Simulator 或 Emulator
* 未能覆盖的部分及原因

不要只输出“验证通过”。必须说明实际执行了哪些操作。

## 完成标准

只有满足以下条件时，才能报告验证通过：

* 已经在选定设备上实际启动应用
* 已经使用 `agent-device` 完成相关交互路径
* 已经观察并确认预期结果
* 没有发现阻断性错误
* 已经完成必要的环境清理
