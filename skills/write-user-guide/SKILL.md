# 编写使用指南

以用户要完成的任务组织内容，用真实界面校准操作步骤，用源码解释行为边界。交付可阅读、可导航、经过检查的文档，而不是功能罗列或测试报告。

## 1. 确定范围与现有约定

- 读取文档与产品仓库的指导文件，检查 Git 状态，保留已有改动。文档仓库与应用源码可能不在同一目录。
- 确认目标读者、产品版本、平台、语言、文档位置及可用测试环境。优先从上下文和项目中获得；只有答案会改变工作结果时才询问。
- 检查目录、导航、已有章节、图片约定、组件、链接写法和构建命令。不要为了写手册更换文档框架。
- 新建指南时，先覆盖首次使用和核心任务；完善旧指南时，保留仍然准确的章节及图片，优先修复误导性步骤和关键缺口。
- 将多步骤工作记录为待办。可把只读源码核对交给子 agent；同一设备的状态操作保持串行，同一文件的写入只交给一个负责人。

## 2. 建立轻量证据清单

在本地临时工作记录中维护以下信息，避免把推断写成实测结论：

| 用户任务 | 当前文档缺口 | 源码或官方依据 | 实际操作结果 | 截图 | 待确认项 |
| --- | --- | --- | --- | --- | --- |

- 从实际 UI 获取入口、按钮标签、菜单顺序、权限提示及成功状态。
- 从当前源码核对默认值、限制、数据格式、持久化、删除语义及平台分支。记录内部文件行号，但不要把实现细节塞入普通用户教程。
- 遇到源码与设备表现不一致，先检查运行版本、构建和功能开关，不要混合两个版本的行为。
- 区分“已执行且验证结果”“仅看见入口”“源码确认”“尚未确认”。看见同步按钮不等于同步成功；看见导出菜单不等于导出文件正确。
- 对外部网站、系统操作或第三方兼容性等可变事实，查阅当前官方资料；无可靠依据时收窄措辞或列为待验证，不编造。

## 3. 操作产品并采集证据

- 移动端或原生应用操作前加载可用的 `agent-device` skill，并遵循当前安装版本的帮助；网页使用共享浏览器。CLI 通过实际命令输出验证。
- 发现设备和已安装应用后再打开目标，不猜包名、设备 ID 或开发服务器地址。确认进入业务页面，而非启动器、Expo 壳或系统桌面。
- 优先复用已有测试数据。不要清空、卸载、批量删除、覆盖歌单或操作真实账号数据来凑截图。必要的写操作使用独立测试对象；可能破坏数据的操作先取得授权。
- 环境无法启动时，做有限诊断。旧 dev client 与当前依赖不匹配时，不把闪退直接归为产品功能错误；覆盖安装、重建原生环境等范围扩展先确认。签名不兼容时停止，不自动卸载。
- 只启动必要服务，记录哪些是本次启动的；结束时停止自己启动的进程，不停止用户原有服务。
- 按“打开 → 快照 → 操作 → 验证目标状态”循环。使用最新快照引用，不复用过期元素；异步加载等待明确目标，不通过重复盲点或固定休眠猜测。
- 先处理开发浮层、键盘或错误遮挡，再截图。工具返回空树或超时时，使用截图判断；不要把空树认作空页面。
- 无可用环境时，继续完成可独立验证的文字工作，但明确未实测范围；不得生成假截图，或以源码核对冒充完整验收。

## 4. 制作有用的截图

- 仅为难找入口、关键界面、选项含义或成功状态配图，不对每次点击都截图。
- 采集真实产品画面；检查通知、账号、路径、二维码追踪参数、令牌及个人内容。使用安全测试内容或必要脱敏，不能把凭据写入文档或 Git。
- 保留原始证据在仓库允许的临时目录中；仅把选定、处理后的图片放入正式资源目录。不提交日志、设备标识或无关桌面截图。
- 用项目已有图片工具压缩和缩放，优先静态 WebP/PNG；不要修改 UI 外观来伪造功能。保留可读文字，限制页面显示宽度，并适配窄屏。
- 实际查看处理后的图片，排除空白、加载态、开发菜单、裁切错误和状态不一致。单有截图路径不算检查过图像。
- 使用描述性文件名、具体 alt 文本及必要图注；标明截图平台，勿把 Android 截图当作 iOS 已验证证据。
- 将图片放在对应步骤或章节内，不放到下一个无关标题下面。沿用现有图片组件与导入约定。

## 5. 编写或完善指南

- 按任务拆章，例如：开始使用、查询或添加内容、核心操作、列表管理、下载与离线、备份迁移、设置、常见问题。只建立产品实际需要的章节。
- 每个任务说明必要前提、入口、编号步骤、预期结果和重要限制。采用准确界面标签；图标按钮补充形状或位置说明。
- 从新用户视角区分容易混淆的概念，例如缓存与导出文件、播放队列与收藏歌单、本地副本与远端同步。
- 对删除、覆盖、解绑、迁移和批量操作说明影响范围，必要时提醒先备份；明确备份包含及不包含什么。
- 不承诺“完全不联网”“绝不丢数据”“所有设备兼容”“固定几秒完成”等未经证明的结论。隐私、性能与兼容性说明必须有相应证据。
- 写明平台差异、功能前提或版本差异，避免将开发者选项作为普通用户操作。没有实测的平台，不声称已验证。
- 保持仓库原有的专业文风，不把对话口癖写入指南。不要贴入冗长源码、调试过程或内部测试报告。
- 更新导航及相关页链接；复用已有详细章节，避免维护多份相同流程。对不在本次范围内的过时内容，在交付说明中指出，不暗示整个手册已完全更新。

## 6. 验收与交付

- 检查标题层级、入口名称、步骤顺序、图片位置、资源引用、相对链接及导航可达性。
- 运行仓库规定的文档构建、链接检查或相关测试，并运行 `git diff --check`。将失败与非阻断警告分别说明，不修改无关配置来掩盖警告。
- 条件允许时预览生成页面，检查桌面和窄屏排版、图片可读性及页面跳转；未做视觉预览时如实说明。
- 对照证据清单检查：有无把看到入口写成操作成功、有无跨版本或平台推断、有无未使用图片和临时文件进入变更。
- 确认没有破坏测试数据，处理本次创建的测试对象时遵循已授权的清理范围，关闭自己的自动化会话和服务。
- 最终简述新增或修改章节、截图数量、验证结果、未验证范围及环境变更，并提供可打开的文档链接。
- 除非用户明确要求，不提交或推送；要求提交时仅暂存本次明确修改的文件。
